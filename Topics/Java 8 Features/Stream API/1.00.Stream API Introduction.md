# Java Streams — Explained for a Beginner

## Imagine this real-life scene first

You have a basket of fruits. You want to:
1. Pick only the **red** fruits
2. **Wash** each one
3. Put them in a **new basket**

That's it. That's basically what a "Stream" does — except the fruits are your data (numbers, names, objects) and the picking/washing are things you want to do to that data.

## Why did Java even create this?

**The OLD way (before 2014):** You had to write a loop, by hand, every single time you wanted to do something with a list.

```java
List<String> names = Arrays.asList("Ravi", "Anu", "Kiran", "Amit");
List<String> result = new ArrayList<>();

for (String name : names) {          // go through each name one by one
    if (name.startsWith("A")) {      // check: does it start with A?
        result.add(name.toUpperCase()); // if yes, make it CAPS and save it
    }
}
```

This works fine. But look how much "bookkeeping" code you had to write just to say **"give me names starting with A, in capital letters."** That simple sentence turned into 5 lines of loop machinery.

**The NEW way (Streams):**

```java
List<String> result = names.stream()
        .filter(name -> name.startsWith("A"))
        .map(String::toUpperCase)
        .collect(Collectors.toList());
```

Read it out loud like English:
> "Take names → **filter** (keep only) the ones starting with A → **map** (change) them to uppercase → **collect** them into a list."

That's genuinely all Streams are: **a shorter, cleaner way to say what you want, instead of writing the loop yourself.**

## Let's break every word down, one at a time

Think of a Stream like a **conveyor belt in a factory**. Items go in one end, pass through a few machines, and come out the other end.

```
names.stream()  ->  .filter(...)  ->  .map(...)  ->  .collect(...)
   (start belt)      (machine 1)       (machine 2)     (end: collect result)
```

| Word | What it really means | Real-life version |
|---|---|---|
| `.stream()` | "Start the conveyor belt" using this list | Turning on the belt |
| `.filter(condition)` | "Only let through items matching this condition" | A machine that removes fruits that aren't red |
| `.map(change)` | "Change every item into something else" | A machine that washes each fruit |
| `.collect(...)` | "Now put everything into a real basket/list" | Packing washed fruits into a new basket |

**Important beginner rule:** Nothing happens on the belt until you tell it to `.collect()` (or do something similar at the end). Until then, it's just a *plan*. This confuses everyone at first — so just remember: **the belt only turns ON when there's a final step (like collect, forEach, count) at the end.**

## The two types of steps, explained simply

**1. Middle steps (called "intermediate")** — these are the machines on the belt. You can have as many as you want, one after another. Examples: `filter`, `map`, `sorted`.

**2. The last step (called "terminal")** — this is what actually finishes the job and gives you a real result (a list, a number, a yes/no). Examples: `collect`, `count`, `forEach`. You only have **one** of these, and it's always at the end.

```java
names.stream()          // start belt
    .filter(...)         // middle step
    .map(...)             // middle step
    .collect(...);        // LAST step -- this is what makes it actually run
```

## Now let's slowly go through the toolbox

### Starting a stream
```java
list.stream();        // most common -- start from a list you already have
```
That's the only one you need to remember for now. (There are other ways, but let's not overload you.)

### `filter` -- "keep only what I want"
```java
numbers.stream()
    .filter(n -> n % 2 == 0)   // keep only even numbers
    .collect(Collectors.toList());
```
Read `n -> n % 2 == 0` as: "for each number `n`, check if it's even."

### `map` -- "change each item into something else"
```java
names.stream()
    .map(name -> name.toUpperCase())   // turn every name into CAPS
    .collect(Collectors.toList());
```
`filter` removes things. `map` transforms things. That's the #1 difference beginners mix up.

### `collect` -- "give me back a real list"
```java
.collect(Collectors.toList());   // pack results into a List
```

### `forEach` -- "just do something with each item, don't need a list back"
```java
names.forEach(name -> System.out.println(name));  // just print each one
```

### `count` -- "how many are left after filtering?"
```java
long total = numbers.stream()
    .filter(n -> n > 10)
    .count();
```

That's genuinely 80% of what you'll use daily. Everything else builds on these four.

## One tiny complete example, explained line by line

```java
List<Integer> ages = Arrays.asList(15, 22, 18, 9, 30, 12);

List<Integer> adults = ages.stream()        // 1. start the belt with the ages list
        .filter(age -> age >= 18)           // 2. keep only ages 18 or older
        .collect(Collectors.toList());      // 3. pack the results into a new list

System.out.println(adults);  // [22, 18, 30]
```

Say it in plain English before you even look at code: *"From all ages, keep the ones that are 18 or above, and give me that list."* Then the code is just typing that sentence in Java's grammar.

## Basic practice problems (start here, one step at a time)

Try to first say the problem out loud in plain English ("keep only... then...") before writing code. That sentence IS your stream pipeline.

1. From a list of numbers `[3, 8, 15, 22, 7, 40]`, keep only the numbers greater than 10.
2. From a list of names, convert every name to lowercase.
3. From a list of numbers, count how many are even.
4. From a list of words, print each word on a new line (no need to collect into a list).
5. From a list of numbers `[5, 12, 8, 20, 3]`, keep only numbers greater than 10, then print how many are left.
6. From a list of names, keep only the ones that have more than 4 letters.
7. From a list of prices, add 10% to every price (hint: this is a `map`, not a `filter`).
8. From a list of numbers, filter out the negative ones, then print the remaining list.

Once these feel comfortable, we'll move to the classic interview-level problems (grouping, sorting, finding max/min, etc.) — same style, just one notch harder.
